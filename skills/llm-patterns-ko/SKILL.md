# $llm-patterns-ko — LLM 고착 패턴 진단

## 목적

LLM을 처음 접했거나 익숙하지 않은 사용자가 모델의 낯선 행동을 이해하도록 돕는다.
사용자가 “왜 이런 일이 일어났는가”를 물으면 반복 편차를 P-001~P-012 중 하나로 분류하고 모델의 사전 경향, 관성, 습관이 어떤 영향을 주었는지 설명한다.
진단과 원인 설명까지만 수행하고 모델의 행동을 직접 교정하거나 변화시키는 스킬로 제시하지 않는다.

## 입력

1. 사용자가 지적한 현상이나 반복 편차를 확인한다.
2. 적용 중이던 규칙·스킬·도구·컨텍스트가 있었는지 확인한다.

## 진단 절차

1. 해당 행동을 요구하거나 제한하는 규칙이 실제 컨텍스트에 있었는지 판별한다.
2. 규칙이 없었거나 전달되지 않았다면 `규칙 가시성 문제`로 분류한다.
3. 규칙이 보였는데도 반복되었거나 규칙과 무관한 확률적 편차라면 아래 카탈로그와 대조한다.
4. 가장 직접적인 패턴 하나를 주 분류로 고르고, 겹치는 패턴은 보조 분류로만 적는다.
5. 출력은 `분류 → 관측 근거 → 인과` 순서로 작성한다.

## 패턴 카탈로그

### P-001 구조화 데이터 주의 편향

다수의 중첩 필드가 한 번에 들어오면 행동 지향 필드가 교정·부정 필드보다 먼저 사용되어, 컨텍스트에 존재하는 `mistakes`, `rejections`, `drift` 등이 추론에서 빠지는 패턴이다.
구조화 데이터가 있었는데 특정 필드군만 반복적으로 누락될 때 적용한다.

### P-002 오류 귀인 자책 편향

오류를 지적받았을 때 실제 원인 분류보다 “내가 실수했다”, “더 주의했어야 했다” 같은 책임 수용 문구가 먼저 나오는 패턴이다.
원인이 규칙 위반인지 구조적 패턴인지 확인하지 않고 자책으로 귀인이 닫힐 때 적용한다.

### P-003 컨텍스트 희석

규칙·설명이 누적될수록 개별 규칙의 상대 신호가 약해져 짧은 문서에서는 작동하던 규칙이 긴 컨텍스트에서 반복적으로 누락되는 패턴이다.
규칙을 더 추가할수록 준수율이 나빠지는 현상에 적용한다.

### P-004 Helpful Over-delivery

확인·조회·읽기 같은 좁은 요청을 분석·제안·실행·선택지 나열까지 자동 확장하는 패턴이다.
사용자 요청의 문자적 범위보다 “더 유용한 답”을 만들려는 방향이 주도권을 선점할 때 적용한다.

### P-005 Reliability-Weighted Knowledge Conflict

파라메트릭 지식과 검색·컨텍스트 증거가 충돌할 때 prior의 확신도, 정보 인기도, 외부 증거의 일관성과 신뢰도에 따라 어느 쪽이 우세한지가 달라지는 패턴이다.
구 이름 `Parametric Memory Fallback`처럼 “항상 prior로 회귀한다”로 단정하지 않는다. 잘못된 검색 증거가 올바른 prior를 덮는 역방향도 포함한다.

### P-006 Conditional Branch Attention Dilution

스킬이나 절차 안에 조건 분기와 모드가 많아질수록 일부 분기 조건이 누락되고 다른 경로로 이탈하는 패턴이다.
같은 분기 위반이 규칙 추가 뒤에도 반복될 때 적용한다.

### P-007 Length-Induced CoT Degradation

긴 컨텍스트에서 직전 추론에 자기조건화되고 새로운 옵션 탐색이 약해져 “더 개선 불가”, “이게 한계” 같은 조기 종결이 늘어나는 패턴이다.
같은 질문을 새 세션에 넣었을 때 즉시 새로운 대안이 나오는 경우 강한 진단 신호로 본다.

### P-008 Test-Suite Reward Hacking

명세를 만족시키기보다 보이는 테스트 통과를 목표로 테스트 수정, 하드코딩, 특수 케이싱 등으로 보상 대리지표를 최적화하는 패턴이다.
테스트는 통과하지만 실제 요구사항을 위반할 때 적용한다.

### P-009 Package/API Hallucination

실제 환경을 조회하지 않고 학습된 이름 패턴을 재구성해 존재하지 않거나 폐기된 패키지·API·심볼을 자신감 있게 생성하는 패턴이다.
P-005와 달리 핵심은 지식 충돌이 아니라 검증 근거 부재 상태의 파라메트릭 생성이다.

### P-010 Action Repetition Loop

상태 변화가 없는데도 같은 도구와 같은 인자를 반복 호출하거나 같은 실패 행동을 재생하는 패턴이다.
직전 thought/action이 다음 행동을 다시 조건화해 step budget을 소비할 때 적용한다.

### P-011 Cascading Failed Edits

첫 편집이 파일 상태를 악화시킨 뒤 기준 상태로 되돌리지 않고 계속 이전 패치를 덧대어 손상을 누적하는 패턴이다.
수정할수록 syntax·구조 오류가 연쇄적으로 늘어날 때 적용한다.

### P-012 In-Session Sycophantic Anchoring

사용자 푸시백이나 직전 자기 결론에 과도하게 동조해 정답을 번복하거나 기존 결론을 더 강하게 합리화하는 패턴이다.
P-007과 달리 핵심 트리거는 컨텍스트 길이보다 사용자 반론·직전 결론이다.

## 구조적 해석 기준

1. 반복 위반은 “더 주의” 문제가 아니라 구조 문제인지 먼저 본다.
2. 텍스트 규칙 누적으로 해결 가능한지보다 경로·스키마·도구·출력 구조가 모델의 기본 확률과 어떻게 경쟁하는지 본다.
3. 금지 규칙보다 원하는 행동이 최소 저항 경로가 되도록 설계된 정도를 본다.
4. 여러 규칙을 더하는 해결책은 P-003과 P-006을 다시 만들 수 있는지 확인한다.

## 출력 형식

1. `주 분류: P-00X — 이름`
2. `관측 근거:` 사용자가 제시한 현상 중 패턴과 직접 맞는 신호
3. `인과:` 왜 이 패턴이 해당 결과를 만들었는지 1~3문장
4. 겹치는 패턴이 있을 때만 `보조 분류:` 한 줄을 추가한다.

## 완료 조건

- 주 분류가 하나로 명확하다.
- 사용자가 제시하지 않은 원인을 사실처럼 추가하지 않는다.
- 진단 요청에서 처방 실행으로 범위를 넓히지 않았다.
